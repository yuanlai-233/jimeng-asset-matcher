## 2026-09-10 画布自动上传（v0.3.13）

新版无限画布视频节点现在也提供普通版的两步流程：**自动上传 → 手动点击自动匹配**。先从选定文件夹递归索引名称，只上传提示词精确引用的图片；随后通过当前节点的原生 `@` /“引用参考”菜单匹配，并保留原文字、追加原生标签。上传后不会自动开始匹配或生成。

- 同一图片引用多次只上传一份，各个引用位置分别匹配；改提示词只补传新增图片。
- 待确认批次会阻止重复上传；同一画布节点重新挂载、切换回来后，仍保留当前页面会话中的上传记录。不同节点独立记录。
- 空提示词、错误 @、空目录、同名冲突、缺失文件和零字节图片会停止上传。常见图片在交接前解码检查，损坏文件会阻止整批上传；HEIC/HEIF 由网页原生上传器校验。
- 画布 Seedance 2.0 / 全能参考实测原生提示最多 **12 个素材**，预检会计入已有的图片、视频和音频；这不是普通页 Seedance 2.5 的 30 张图片上限，也不保证每种媒体都能占满 12 项。
- 修复画布协同同步产生相同文档副本时的误停止；仍核验完整文档、原素材名和光标，实际改字或切节点会停止操作。

该历史版本的自动文件夹上传只处理图片；v0.3.17 起已支持图片、视频、音频。已通过原生入口上传的视频仍可自动匹配。刷新页面会清除本地文件夹和上传记录；已有附件的任务应先“自动匹配”核对，避免把刷新后的会话当成首次空任务。

## 它帮助你做什么

- **自动上传引用素材**：只读取提示词中显式 `@完整素材名` 与本地文件名精确一致的图片、视频和音频，未引用文件不会上传。
- **追加网页原生参考引用**：保留 `@素材名` 文字占位，在后面追加网页自己的原生素材标签，不删除、不替换原文字。

- **保持用户控制**：“自动上传”和“自动匹配”必须分别由用户点击，扩展不会自动发送或生成任务。

## 首次使用

扩展第一次识别到可用创作框时会自动显示一页中文说明。点击“开始使用”后会记录已读，以后不再自动弹出，也不会在控制条常驻“说明”按钮。最短流程只有两步：

1. 提示词中写出与素材文件名（去掉扩展名）完全一致的 `@完整素材名`，然后点击“自动上传”。
2. 页面接收完素材后，再点击“自动匹配”。扩展保留原来的文字占位，并在后面追加网页原生素材标签。

目录授权只在当前页面会话中保留；刷新页面后需要重新选择。说明页中的“忘记已选文件夹”可立即清除当前会话的句柄和索引。

## 核心规则

- 原来的文字占位 `@素材名` 始终保留，不删除、不替换。
- 原生素材标签必须紧邻追加在对应文字后面。
- 每个文字位置单独校验；同名素材出现三次，就分别拥有三个配对槽。
- 普通正文同名不处理，只有显式 `@完整素材名` 才参与上传和匹配。
- 不做模糊、语义或前缀猜测。`@123` 不会命中 `@1234`。
- 每个槽在一次运行中最多点击一次候选；点击结果不确定时立即停止本轮，不自动重击。
- 自动匹配调用网页原生 `@` 工具按钮；新版普通页与画布在严格核验后可追加一个临时 `@`，供原生菜单生成标签或安全清理，原文字占位不会被替换。
- 点击“自动匹配”时会在 `pointerdown` 阶段锁定当前编辑器并保持焦点；匹配期间暂时隐藏扩展控制条，避免它遮住素材弹层，结束后再恢复。
- 扩展不会未经二次确认自动发送或生成任务。

## 自动上传流程

1. 读取当前活动提示词编辑器。
2. 由用户选择一个外层素材文件夹；当前页面会话内可复用，刷新后重新选择。
3. 递归扫描所有子文件夹，只建立并缓存轻量文件名索引；此时不会读取全部文件内容。
4. 用当前提示词中的显式 `@完整素材名` 与本地索引求精确交集，再排除本任务中已经由“自动匹配”逐名确认的文件。无本地交集时立即停止，不上传，也不打开网页原生 `@` 菜单。
5. 仅对尚未确认的交集素材调用 `getFile()`；重复引用只上传一份文件。
6. 按媒体类型检查文件，常见图片额外进行解码预检；视频和音频的编码、时长交由网页校验。再使用当前创作框的网页原生上传入口提交文件，并以 `onFilesDispatched` 确认文件已经真实交给网页上传入口。
7. 等待本批上传状态完成后，“自动上传”立即停止；本批名称保留为 pending，不打开原生 `@` 素材目录、不写账本，也不追加标签。
8. 用户另行点击“自动匹配”后，扩展直接使用本地缓存的 pending 精确名称逐项打开原生候选并匹配；不先滚动扫描整份网页目录。正常批次的所有名称都得到原生标签确认后，才写入当前任务的“已验证上传”账本并清除 pending。

自动上传严格采用 folder-first 顺序，而且与匹配严格分成两个手动阶段。整次“自动上传”从扫描到页面确认完成期间，打开原生菜单、扫描候选目录、输入裸 `@` 和点击候选的次数都必须为 0；扩展不会为了制定上传计划或上传后核验而临时读取网页原生素材目录。上传计划只能使用本地索引，以及此前已经由用户手动运行“自动匹配”核验得到的本任务账本。

FileList 赋值、上传 Promise 返回或页面缩略图数量都不能单独让名称进入账本。只有用户点击“自动匹配”，并让每个 pending 名称至少得到一个同名原生标签确认后，才会写入。同一任务再次点击“自动上传”时，账本中的文件会直接跳过，不再打开网页 `@` 目录进行上传前查询，也不会再次 `getFile()` 或重传。真正提交/清空并切换任务时，账本随任务重置。

pending 对账只判断本批 pending 名称本身。若提示词还引用网页手动上传的素材，匹配会读取完整目录，在同一轮处理本地与网页手动上传的图片、视频、音频。本地 A 生成原生标签后正常入账；其他名称缺失也不会使已确认的 A 重复上传。

如果网页明确报告整批中至少一张上传失败，扩展不会立即重传整批，因为其中可能已有部分成功。用户先点击一次“自动匹配”核对成功项；已出现的名称写入账本，未出现的名称解锁。之后再次点击“自动上传”时，只补传仍缺少的文件。

没有 pending 时，用户手动运行“自动匹配”仍会读取完整、非空的权威素材目录，并据此逐名校准账本。例如账本是 A+B、网页目录只剩 B，本轮只从账本移除 A、保留 B，不会立刻上传；下一次点“自动上传”只补传 A，且本次自动上传全程不会产生新的网页 `@` 操作。pending 本地名称集合不是完整网页目录，因此绝不能用它修剪旧账本。空目录可能只是瞬时渲染失败，也不会用来清空整本账。

大批图片在即梦中可能只显示为一张叠卡。扩展采用两阶段确认：

- 若页面给出足够数量的新增预览、列表项或成功计数，等待本批状态稳定后结束“自动上传”。
- 若多文件被聚合成少量叠卡，则在本批叠卡从忙碌变为空闲后结束“自动上传”。如果网页极快地创建并移除转圈，扩展也会在新增叠卡保持短暂安静后结束，不再无意义等待到 30 秒。这只代表页面已经接收本批文件，不代表每个名称已经写入账本。

上传监听会在文件交给网页之前安装，并优先覆盖已验证的完整创作框区域，以免漏掉文件输入框同级的缩略图；DOM 变化会合并处理。无法确定局部范围时不监听整页突变，只做低频兜底检查。进度判断不会反复读取整页提示词和历史内容，减少大页面上的卡顿。

页面其他区域的 loading 不计入本批上传状态。已经触发 `onFilesDispatched` 的待确认批次会按编辑器锁定：再次点“自动上传”既不会重传，也不会打开 `@` 菜单；等待素材名称出现后，应手动点“自动匹配”，按本地精确名称逐项查询并追加标签。任一候选缺失、点击结果 uncertain 或最终邻接校验失败时，pending 继续保留，稍后可再次手动点击“自动匹配”。

## 原生 @ 匹配流程

1. 只有用户点击“自动匹配”才启动本流程；“自动上传”不会自动串联进入这里。
2. 按钮的 `pointerdown` 先锁定当前活动编辑器并阻止网页抢走焦点；匹配全程只操作这个编辑器，并暂时隐藏扩展控制条。
3. pending 上传批次与已验证名单能覆盖全部提示词引用时，直接使用这些精确文件名，不扫描完整目录，也不用局部集合修剪账本。
4. 没有 pending，或提示词还包含名单之外的网页素材时，读取并复用完整原生目录，让混合素材在同一轮处理。
5. 从提示词末尾向前处理，避免前面的 DOM 变化影响后续文字位置。
6. 把光标精确定位到原始 `@完整素材名` 的末尾；同步当前编辑器 Selection，重新取得存活的工具栏，再点击原生 `@` 按钮。新版 ProseMirror 编辑器建立一个独立、受文档与选区校验的临时 `@` 查询，防止原生菜单复用并替换源文字。
7. 在本次活跃弹层中逐项查找并点击完整同名候选，不再次输入文件名搜索；每个槽最多点击一次。
8. 只有原文字逐字未变，且其后第一个有效 DOM 单元是同名原生 mention，才算该槽成功。所有 pending 名称均确认后才写账本并清除 pending。

空格、标点或普通文字隔在原文字和原生标签之间时，不算紧邻配对。Slate 的零宽光标字符可以忽略。

旧 Slate 路径不写入触发字符。新版普通页和画布只允许在完整文档与选区匹配时插入一个扩展拥有的临时 `@`。未点击候选时，只有删除该字符后能恢复整个原文档才清理；普通页若保留临时字符并新增原生标签，也必须验证唯一变化为该字符及其紧邻的一个原生标签，才删除临时字符。真实改字或旧标签属性变化会阻止清理，不猜测重写用户内容。候选一旦已经点击但网页迟迟没有确认，扩展不会再点击第二次，也不会继续下一槽；稍后再次手动运行时会先检查是否已经晚到成功。

失败或 uncertain 的运行不会执行“可能多传素材”审计，也不会再弹出“发现未使用的上传素材”对话框；只有使用完整权威目录且全部槽成功时才允许这项审计，避免失败提示与多传提示双弹。

新一项开始前必须确认旧素材弹层已经关闭。仍在退出动画或无法关闭的旧弹层会阻止下一项，避免多个候选框堆叠和误点。

### 即梦无限画布的横向工具栏

无限画布会把提示词底部工具栏做成横向分页：原生 `@` 可能仍挂载在当前卡片右侧但被裁剪，也可能在翻到下一页前根本不挂载。当前版本会在每次需要打开素材菜单时自动处理，不再要求用户先手动点击工具栏右箭头：

- 先等待编辑器 focus 引起的工具栏重绘稳定，再查找当前提示卡所属的原生 `@`；
- 被裁剪的 `@` 只有与当前 editor 共享紧凑 composer DOM 作用域时才可使用，历史卡片和页面级同形按钮不会被选中；
- 若 `@` 尚未挂载，只允许点击同一 composer、同一工具栏内未禁用且带明确“下一页 / right / next / pager”语义的控件，或经屏幕坐标变换后可确认朝右的未禁用匿名 chevron；旋转成上箭头的发送键以及生成、上传、删除按钮均会被排除；
- 翻页后重新解析原生 `@`，每个槽设置 caret 后再等待一个微任务并重新绑定工具栏节点，兼容 Slate Selection 同步和工具栏 remount；
- 素材弹层关闭后工具栏即使再次回到第一页，下一槽也会重新安全揭示 `@`；旧画布路径不会向提示词输入裸 `@`，不会删除或替换原文字。新版画布只在原生按钮复用旧查询时追加一个受校验的临时 `@`，候选标签由网页原生菜单创建。

## 大素材目录与虚拟列表

素材较多时，原生菜单只会挂载首屏约 16—17 行。扩展会：

- 只锁定当前活跃且带素材菜单语义的弹层；
- 识别真正的滚动视口；
- 根据挂载行内容变化逐屏读取虚拟列表；
- 到达当前底部后继续确认是否还有懒加载内容；
- 页面显示“全部（29）/ 图片（29）”时，少于 29 项会停止，不会用半份目录继续匹配；
- 只缓存规范化后的名称字符串，不缓存候选 DOM、Range 或 Selection。

账号主体库、`Octo`、“创建主体”“灵感”“生成”“资产”“画布”“参考内容”以及促销卡片不会进入当前上传素材目录。

## 安装

1. 打开 Chrome 的 `chrome://extensions/`。
2. 开启右上角“开发者模式”。
3. 如果已加载旧版，可更新原目录后点击该扩展的“重新加载”；避免同时安装多个版本。
4. 点击“加载已解压的扩展程序”。
5. 选择克隆或解压后的项目目录（其中应直接包含 `manifest.json`）。
6. 回到即梦 / Dreamina 页面并强制刷新。
7. 在扩展管理页打开“即梦素材一键匹配”详情，确认版本为 `0.3.24`。

如果浏览器中还安装了本项目的旧油猴脚本，请先在 Tampermonkey 中禁用或删除。旧脚本抢先运行可能阻止扩展初始化。

## 使用

### 推荐：从本地文件夹自动上传

1. 文件 `03_产品特写.png` 在提示词中写作 `@03_产品特写`。
2. 点击“自动上传”，选择包含角色、昆虫、场景等子文件夹的外层目录；刷新页面后需要重新选择。
3. 扩展先缓存目录文件名，再按当前提示词求精确交集并上传；页面确认上传完成后停住，不会自动打开 `@` 菜单或开始匹配。
4. 上传完成后，手动点击“自动匹配”；扩展直接按本地缓存的 pending 精确名称逐项查询并追加原生标签，不先扫描完整目录。
5. 按住 `Shift` 再点“自动上传”，可重新选择或强制重扫同一文件夹。
6. 不同子目录若存在相同去扩展名，扩展会在读取文件和上传前停止，并只显示冲突名称与数量，不把本机路径写进网页。
7. 同一任务再次点“自动上传”时，已经由“自动匹配”确认生成原生标签的文件会由任务账本直接跳过，不重复读取或上传；提交/清空并进入真实新任务后会重新建立账本。
8. 若在当前任务删除了部分已验证素材，先手动运行一次“自动匹配”读取完整非空目录，让账本只移除实际缺失的名称；再点“自动上传”只补传这些缺失文件，仍存在的素材不会重传。

### 手动上传后匹配

1. 先在即梦 / Dreamina 上传图片、视频或音频。
2. 在提示词中写出完全同名的 `@完整素材名`。
3. 点击“自动匹配”。
4. 检查每段原文字后是否紧邻出现对应的原生素材标签。

再次点击不会给已配对槽重复插入。若当前素材目录中存在提示词未使用的上传素材，状态灯会保持黄色并要求“返回检查”或“确认保留”。

## 状态与发送保护

- “自动上传”“自动匹配”和状态灯只显示在当前活动的创作 composer 卡片右上角；空闲时随卡片定位，匹配期间整组暂时隐藏，避免覆盖网页原生素材弹层，结束后恢复。
- 进入生成结果详情、预览遮罩、历史内容或其他没有活动创作输入框的页面时，整组控件隐藏，不悬浮在页面内容上。

- 暖黄色“待匹配 N / 待检查”：仍有未配对文字、缺失素材或待确认的多传素材。
- 绿色“✓ 已匹配”：当前提示词中的素材槽均已配对，且多传检查已处理。
- 只点击提示框、移动光标或改变选区不会清除绿色；插件会等待 Slate 稳定后比较提示词原文与原生标签配对状态。只有真实改字、删除/错位原生标签、改变上传素材或切换任务才重新变黄。
- 点击发送或按 Enter 时会先出现二次确认；Shift+Enter 仍用于换行。
- 修改提示词、素材缩略图或切换任务会使成功状态重新进入待验证。

未配对位置使用浏览器 Range 与编辑器外部红色覆盖层标记，不向 Slate 内插入自定义标签。

## 文件、权限与隐私

自动上传首版支持：`avif`、`bmp`、`gif`、`heic`、`heif`、`jpeg`、`jpg`、`png`、`webp`。

扩展只注入即梦国内站和 Dreamina 海外站，不申请浏览历史、Cookie、下载、标签页、剪贴板或任意网站访问权限。唯一普通权限 `storage` 只保存“首次使用说明已读”这一布尔值。

- 插件没有自建服务器、统计、广告或遥测，也不会把提示词、目录索引发送给插件开发者。
- 用户点击“自动上传”后，插件会递归读取所选目录及子目录的文件名；只有与显式 `@完整素材名` 精确命中的图片、视频或音频内容会交给当前即梦 / Dreamina 页面上传，随后由该目标网站按其隐私政策处理。
- 文件夹句柄和索引只保存在当前页面内存，刷新或关闭页面后失效。`v0.3.7` 启动时会删除旧版曾写入目标网站 IndexedDB 的目录句柄数据库。
- 扩展注入页面的提示不会展示本机根目录名或冲突文件的相对路径。

完整说明见 [PRIVACY.md](PRIVACY.md)。

## 排错

- 看不到按钮：确认位于视频生成页面，重新加载扩展后强制刷新网页。
- 仍显示旧行为：在扩展管理页检查版本是否为 `0.3.24`，重载扩展后保存提示词并刷新即梦页面。
- 旧提示词里已有单独裸 `@` 或素材名缺字：这是旧版已经写进页面的数据，当前版本不会猜测并自动删除。请先撤销、恢复缺字，或重新粘贴一份干净提示词，再测试新匹配；新版本只会在严格验证后清理自己创建的临时字符。
- 文件夹选择器没有打开：必须由真实点击“自动上传”触发，并使用较新的 Chrome / Edge。
- 点击“自动上传”期间出现 `@` 菜单或上传结束后自动开始匹配：这是旧版流程；当前版本的“自动上传”全程不会调用任何原生 `@` 操作，必须由用户另行点击“自动匹配”，请移除旧扩展后重新加载。
- 点击“自动匹配”后提示框缩小、控制条跟着弹层乱动，或正文出现单独的 `@`：确认已经重载当前版本并刷新网页。本版会在 `pointerdown` 锁定编辑器、匹配期间隐藏控制条，并只通过网页原生 `@` 工具按钮打开候选菜单。
- 无限画布提示“无法通过网页原生 @ 按钮打开素材菜单”：确认已经重载当前版本并刷新网页。本版可自动识别当前提示卡被横向裁剪的 `@`，或安全点击同一工具栏有明确语义/明确屏幕朝向的下一页按钮；无需先手动翻页。若箭头经变换后仍无法与发送键可靠区分，扩展会安全停止而不盲点。
- 已经绿色，只点击提示框就变黄：确认已经重载当前版本并刷新网页。本版不再把 Slate 聚焦时的零宽光标节点重建或无语义 `input` 当成真实编辑。
- 找不到上传入口：确认当前使用“全能参考”模式；多个相似入口存在歧义时扩展会安全停止。
- 提示同名冲突：重命名重复的去扩展名后，按住 Shift 重选/重扫。
- 提示等待网页确认：文件可能已交给页面，但原生目录尚未发布名称；不要再次点“自动上传”。等待素材出现后点“自动匹配”，扩展会先对账，不会重复提交。
- 已删除素材但没有自动补传：先让“自动匹配”成功读到完整且非空的素材目录，再点“自动上传”。空目录不会清空整本账，以免网页瞬时空菜单造成全量误传；若确实已删空，请新建/重置任务或手动处理。
- 候选菜单打不开：确认手动点击网页 `@` 按钮能够看到素材候选。
- 名称未匹配：提示词名称必须与素材菜单显示的完整名称一致，包括括号和名称内部空格。
- 网页改版后失效：在开发者工具 Console 中搜索 `[即梦素材匹配]` 或 `[即梦本地素材]`。

```bash
npm run test:canvas
npm run check
npm run audit:privacy
```

代码职责：

- `matcher.js`：名称规范化与精确槽位计划；
- `runtime.js`：共享运行状态、pending 批次、任务内已验证上传账本与绿色语义快照；
- `onboarding.js`：首次说明已读状态和固定说明文案；
- `local-directory.js`：页面会话内文件夹授权、主动忘记与旧版站点数据库清理；
- `local-assets.js`：递归索引与按需读文件；
- `local-workflow.js`：无副作用上传计划；
- `local-upload.js`：原生文件输入、上传状态与聚合叠卡确认；
- `editor.js`：Slate/ProseMirror 定位、相邻配对和外部标红；
- `candidates.js`：原生菜单、虚拟列表和单次候选点击；
- `native-trigger.js`：等待 focus 稳定、在无限画布横向工具栏中安全揭示并打开网页原生 `@` 菜单、等待 Selection 微任务后重新绑定节点；
- `ui.js`：按钮 `pointerdown` 编辑器锁定、匹配期间控制条隐藏、状态灯、提示、绿色语义快照、发送确认与真实任务 reset；
- `content.js`：上传、账本过滤/写入、仅对完整权威目录执行修剪、pending 精确名称逐项匹配、最终邻接验证与 Slate 稳定态重算。
